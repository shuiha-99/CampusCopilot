# 检索开发/回归评测集 v1

这一版固定了 `sources.json` 的6条资料、19个知识块，以及 `cases.json` 的39道题（36道可回答、3道无相关块）。`manifest.json` 保存两个文件的 SHA-256；文件变动时评测脚本拒绝运行，应发布 v2 并重跑所有方案。资料只来自商丘学院公开页面；历史页面的金额或办理步骤不能作为2026年现行通知。

## 标注口径

逐题检查**全部19块**，再给出相关块集合；绝不以某个检索器的前5条结果倒推标签。相关块必须在题目指定的年份和对象范围内直接回答某一问点，或提供解释版本冲突所必需的明确证据。同一答案若分布在不同年份的多个块，均按其年份标注。只碰到同类词、却不能提供所问事实的块不计入。无对应证据的题目标空集合，单独检查检索行为；其结果不进入 Recall@5/MRR 分母。

旧26题在加入2024招生章程和2025助学贷款块后重新逐题检查，按 `origin=legacy_relabelled` 标识来源；原题 `q013` 从容易混淆奖学金与助学金的问法改成国家资助措施，`q026` 改成历史版本差异问题。`q015` 同时标注2024级通知和一般学生规定。`q029` 问2024和2025最高助学金档次，两个年份的数字现在都实际写入快照知识块。三个无相关块问题分别涉及2026申请截止日、食堂现价和校外火箭技术。

每题的 Recall@5 = 前5条中找回的不同相关块数 / 此题全部相关块数；MRR 使用首个相关块的名次倒数。各题算完后取可回答题目的平均值。19块中，最多只能返回5块，所以有超过5个相关块的题即使前5条全对，Recall@5 也不会是100%。

这是项目导师初次人工逐块标注的**固定开发/回归集**，不是盲测或独立测试集。后续若用得分修改融合权重，它仍只能用于开发决策。当前没有第二人独立复核，也没有线上用户抽样；报告这些限制时保留题数、资料范围、Embedding配置和版本号。

运行：从项目代码根目录执行 `.venv/Scripts/python -m scripts.evaluate_retrieval_v1`。脚本单独使用 `v1/chroma_<embedding_provider>` 索引，不修改生产知识库；设置 `EMBEDDING_PROVIDER=hash` 可跑离线基线，设置 `EMBEDDING_PROVIDER=ollama` 且本机 Ollama 可用时跑真实语义模型。同一版本所有模式使用同一资料和题目快照。真实 Embedding 的三种模式结果保存在 `results_ollama.json`，离线哈希基线保存在 `results_hash.json`。

修复前的真实模型探测记录在 `unanswerable_model_probe.json`：两题超时，一题生成伪引用。现有 Agent 在零结果、明确年份缺失或检索内容与问题主题明显不符时保守拒答；模型返回后还检查引用编号，并核对少量明确的年级条件和金额字面值。对 v1 同一固定开发集运行 `.venv/Scripts/python -m scripts.check_answerability_v1`，报告 `answerability_guard_results_ollama.json`：36道有相关块题保留可用候选，3道无相关块题均被拦下。该阈值是在查看这组题后确定的，结果不能当作独立测试成绩，也不能证明候选确实足以回答。

`unanswerable_agent_check.json` 记录了三道无相关块题的真实 Ollama Embedding、MySQL 和进程内 HTTP 问答及 Trace 查询：原始检索候选数依次为5、5、0，三题均返回证据不足、有效引用0、模型调用记录0，`ConversationRun=SUCCEEDED` 表示本次安全答复已成功保存。2026截止日题展示旧资料的日期与 URL 供历史对照，旧资料不算答案引用。`RetrievalRun` 保存原始候选供排查，不是下次问答的缓存。

这套规则不能做语义蕴含证明：词面相关、引用编号存在或资料发布日期匹配，都不保证每句话得到来源支持。真实正常问答曾出现引用编号有效、但具体年级条件不在所引资料中的输出，现以有限字面规则拦截；其他隐含条件和个人资格仍需人工核对最新官方通知。当前知识库与评测快照不同，评测数字不能直接当作线上回答质量。
